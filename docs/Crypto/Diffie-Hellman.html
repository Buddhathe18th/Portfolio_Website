Diffie-Hellman

To the very careful readers, you might just be familiar with the name Diffie-Hellman. These two were the two people that came up with the idea of RSA. The Diffie-Hellman key exchange actually predated RSA, being one of the first models of public key and private key encryption.

Prerequisite Math

Just like RSA, Diffie-Hellman also is based on a trapdoor function. Instead of factoring large numbers, the trapdoor function is something known as the Discrete Logarithm Problem.

Normally, if it was known that \(b^k=a\), its a simple operation of finding \(k=log_b(a)\). Yet, now we operate on a field G, with generator \(g\) (That means that if we take \(g^0,g^1, \dots g^n\) will result in all the values of the field G), and we know \(a=g^k\) then it is not that easy to find the value of \(k\).

For example, if we know \(5^x=3125\), we can take \(log_5\) both sides to find \(x=5\). Yet, if we konw \(5^x\equiv 14 \mod 17\). We see the two examples actually result the same numbers, but we are no longer able to find this in one step, and need to go through a variety of steps. The simpliest method, to try all values of \(x\) has time complexity of O(n) (If you want to know more about time complexity, check out the page about sorting, where I explain this more in depth), which for larger primes is incredibly slow.

Diffie-Hellman algorithm

Imagine Alice and Bob wanted to communicate through an insecure channel, but to securely communicate, they would need to have a key to encrypt the messages. Since the only way to communicate is insecure, they need to use some sort of method to communicate through here. Now, let Alice send Bob a prime, \(p\), as the mod, and \(g\), which is the generator, or base, of the exponent. After that, Alice choses a number \(a<p\) to keep private, which will be known as the Alice's private integer. Then, she distributes \(A=g^a\mod p\) through the insecure channel to Bob. Now, Bob repeats what Alice did, creating his own number \(b\), then finding \(B=g^b\mod p\) as his public number, which he distributes to Alice. Now, what Alice can do is raise \(B\) to the power of \(a\) to get \(S_a=B^a\mod p=\left(g^b\right)^a\mod p=g^{ab}\mod p\). Similarly, Bob will raise \(A\) to the power of \(b\) to get \(S_b=A^b\mod p=\left(g^a\right)^b\mod p=g^{ab}\mod p\), which is equal to \(S_a\). Now, Alice and Bob have the same values, and no one else can solve for this number with the public numbers distributed through the insecure channel.

Common attacks

Insecure random number generators

When creating the public key for RSA, an insecure prime generator can easily comprimise the security of RSA. Imagine when generating your primes, you used a specific random prime generator, which is not quite random, and would cycle the prime it generated. If someone was to use the same generator and figured this out, they could easily test which primes were used. This is not only a security issue if they have the exact numbers, but even a higher probability of a specific number of type of number will impact the security and make it easier to break.
